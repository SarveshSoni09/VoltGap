# Future work

Everything that tempts a redesign mid-build (CLAUDE.md §18.9). Ideas here are recorded
and deliberately **not** acted on.

## Raised in Phase 0

| Idea | Why it is tempting | Why it waits |
|---|---|---|
| Retrieve full Atlas EV Hub state files and reconstruct the complete DMV snapshot series per state | Would turn 14 states into a genuine sub-state longitudinal panel, far stronger than the single Illinois panel, and would strengthen §10.2 deployment alignment considerably | ~3.4 GB across 14 files. Phase 0's job is to establish the contract, not to ingest. This is Phase 1/3 work and should be planned as such, not smuggled into Phase 0. |
| Obtain archived AFDC station snapshots to replace the survivorship-biased reconstruction | Would remove the single largest caveat on §10.2 (domain rule G11) | CLAUDE.md §10.2.5 explicitly routes this here rather than into a redesign. No archive source has been located. |
| Build a ZIP-to-tract crosswalk from HUD USPS crosswalk files | 11 of the 16 states with sub-state registration data are ZIP-grain | Belongs to Phase 3 where the demand model needs it. Recorded as assumption A-0.7. |
| Use the NREL home charging scenario surface at the EV-share slice closest to current fleet penetration, treating it as approximately current | Would let home charging into the primary objective rather than the exploratory index | Choosing a slice is a modelling decision dressed as a data decision. §7.2's fallback is unambiguous once the shares are established as non-current, and Phase 0 established that. Raised as an open question for the reviewer instead. |
| Mirror the CEJST archive copy locally and serve it from R2 | Removes a third-party single point of failure (assumption A-0.10) | Cheap and probably right, but it is Phase 6 hosting work. |
| Per-source drift tolerances calibrated from observed behaviour over several refreshes | The provisional ±20% default is a guess for most sources | Needs several observations to calibrate against. Assumption A-0.13. |
| Probe the AFDC `electric-networks` endpoint to enumerate network names authoritatively | Would help site clustering and the empirical power fallback in §7.1 rung 2 | Not needed for the Phase 0 contract, and the AFDC quota is scarce until a personal key exists. |

## Added by the Phase 0 review (2026-08-19)

| Idea | Why it is tempting | Why it waits |
|---|---|---|
| Give eGRID a consumer: avoided-emissions estimates, electricity carbon-intensity analysis, carbon-aware siting, emissions-per-mile comparison, environmental-benefit scenarios | eGRID is confirmed reachable and the data are good | None of these is required by the Core decision engine. eGRID is demoted to Optional/Future Work (`CLAUDE.md` §7.12). **Do not invent an emissions feature in order to justify keeping the source.** Promote it only if a concrete Core consumer appears |
| Promote home charging access into the primary siting objective | It is one of the strongest available predictors of public charging need | Settled by owner decision A7 and explicitly not reopenable in Phase 3. The NREL dataset is a parametric scenario surface, so any slice of it is a modelling choice. Revisit only if new empirical data materially changes the source situation |
| Regional substation datasets from individual utilities or state agencies | Would restore genuine grid proximity where a trustworthy source exists | `CLAUDE.md` §7.9 already permits this as an *optional* per-region feature with source provenance. It is not Core work and must never become a national constraint by accretion |
| Semantic copy linting beyond phrase matching | Would catch paraphrased optimality and feasibility claims | Owner decision A9 accepts a rule-based guard for Phase 1; Phase 5 may extend it. Do not build an NLP layer for this |

## Raised in Phase 3 (2026-08-28)

| Idea | Why it is tempting | Why it waits |
|---|---|---|
| **Use ZIP registration totals as reconciliation constraints** (external review **decided against this for Core v1** on 2026-08-29; it stays here as future work, not as an open question), via the iterative proportional fitting already implemented and tested | The measured transformation ladder says ZIP-anchored allocation places EV mass substantially better than a state total alone — statewide tract TVD **0.1621 against 0.3049** under a common distribution method. Eleven states have this evidence and the published surface currently rests on their state totals instead. It would also make `zip_anchored` a real evidence grain rather than an unused enum value | Evaluating a new constraint set properly is its own piece of work: it needs its own validation design, its own uncertainty treatment for the allocated component, and a decision about whether a tract bound to a ZIP total may be called sub-state anchored. CLAUDE.md §19 scope control sends a useful enhancement here rather than into the running phase. **Reviewer decision, 2026-08-29: not in Core v1.** "ZIP-grain observations remain valuable training and native-grain validation evidence, but they will not become hard tract-level reconciliation constraints in Core v1. The Washington transformation ladder demonstrates potential value, but one-state evidence is insufficient to justify changing the national reconciliation model and evidence-grain semantics at this stage." Revisit if a second paired state is found |
| A tract-level urban/rural classification from the Census 2020 urban-area products | CLAUDE.md §7.3 names urban/rural as a primary feature, and Phase 3 ships population density as a continuous proxy instead. A classification would let the model treat rural areas as a distinct regime rather than an extreme of one | No keyless tract-level product was retrieved this phase. The block-level urban-area file is large and would need aggregating. Assumption A-3.5 |
| Measure the transformation ladder in a second state | Every published `c4` is a Washington-derived number applied nationally (assumption A-3.2) | Washington is currently the only state whose vehicle rows carry a ZIP, a county and a tract together. A second such source would have to be found first |
| Resolve the New Jersey registration gap against its publisher | Its observed BEV total is 21.65% below the AFDC figure at the same vintage, and its latest snapshot carries one distinct registration date against 36 and 138 for comparable states | Corrected G9 forbids marking a state low-confidence on statistical unusualness alone. Resolving it needs publisher correspondence or a second source, not more arithmetic. Assumption A-3.1 |
| Bootstrap the uncertainty prediction interval over states rather than areas | The dominant uncertainty is arguably which *states* published sub-state data at all, not which areas within them | A 14-state resample is a very coarse bootstrap, and the pre-registration fixed the current definition before fitting. Changing it now would be exactly the post-hoc tuning the pre-registration exists to prevent. Revisit in Phase 5 with the definition fixed in advance |

## Raised in Phase 4 (2026-08-31)

| Idea | Why it is tempting | Why it waits |
|---|---|---|
| **Ingest TIGER roads and implement the real road-network proximity filter** | §7.8 specifies it, and the populated-area filter shipped in its place is strictly weaker: it admits inhabited cells that are far from any road the specification would have excluded | TIGER roads are published per county and are large; a national ingest is its own piece of work. The degradation is labelled everywhere it appears rather than hidden. Assumption A-4.1 |
| A cost model for candidates, so the budget is money rather than site count | Would make the frontier comparable to a real capital plan, and would turn the problem from cardinality-constrained back into the budgeted maximum coverage §7.8 describes | Charger economics is Optional tier (§7.11) and depends on the OpenEI rate database. Inventing a dollar proxy now would fabricate an input. Assumption A-4.4 |
| A composite equity index with a weight-sensitivity control | A single indicator is a narrow view of disadvantage; vehicle access, tenure and language isolation are all defensible | §17 forbids shipping a composite without a sensitivity control, and building that control properly is frontend work (Phase 6). One named indicator was chosen deliberately to avoid hand-picked weights. Assumption A-4.3 |
| Vary the coverage k-ring by cell density instead of using a uniform k = 1 | A ~270 km² service area is generous in a city and possibly tight in rural Montana | Needs a defensible rule for varying it, which is a modelling decision that would want its own validation. Assumption A-4.2 |
| Extend the ε sweep beyond the achievable ceiling of the demand-optimal portfolio | The constraint only binds at the top of the current range, so most of the frontier is flat | The ceiling is what the budget can actually reach; going beyond it produces infeasible points, which is what the first implementation did wrong. A larger budget would be the way to explore further |
| Migrate to PuLP 4.0's `prob.add_variable` and `COIN_CMD` | PuLP 3.x warns that both change in 4.0 | The pinned range is 2.8–3.x and the behaviour is correct today. The warnings are filtered with the reason recorded rather than silenced blindly |
